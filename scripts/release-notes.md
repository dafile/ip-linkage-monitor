# v1.6.4 软重启同步生效：不再残留旧“在线”

## 问题

点击「立即重启服务」后，界面会先显示旧的「蓝牙在线」，几秒后才变成正确的「离线」。
自动定时重启与手动按钮共用同一通道，因此两者都有这个现象。

## 原因

软重启原本是“异步执行”：请求只递增服务代号，等监控线程下一轮循环（最多 3 秒）
才真正重置状态。这段间隙里 UI 仍在读取重启前的旧「在线」；随后新检测用定向寻呼
复核（设备不在时需数秒）才翻成离线。**过程中不会触发联动规则**（重置会清空待执行任务），
但界面观感像“先在线后离线”。

## 修复

- **同步重置**：`request_soft_restart` 在递增代号的同一时刻立即清空在线状态、
  离线确认、待执行任务与蓝牙会话/缓存；点击或定时触发即刻生效。
- **代号守卫**：重置前发出、重置后才返回的在途检测结果会被丢弃，不会把旧结论写回。
- 前端点击后立即把状态区切到「检测中…」，随后自动刷新到真实结果。
- 新增两个单元测试（同步重置、旧代次结果丢弃）；25/25 测试通过。

## 预期

- 点击「立即重启服务」：**立即**显示「检测中…」，随后显示真实状态（离线/在线），
  不会再先闪过旧的「在线」；
- 定时软重启同理，且依然不闪窗、不退出进程、托盘图标不变。
